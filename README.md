# 메이플 스레드 보스봇 — 첫 구현

**디스코드 스레드 하나에서 각자 캐릭터를 여러 개 등록하고, 그 목록으로 여러 파티를 만든 뒤 파티별 보스를 등록하는 봇입니다.** 웹 사이트 없이 실행합니다.

## 현재 구현된 범위

### 2026-11-12 변경 사항 (이전 스레드 전용 설명보다 우선)

- 캐릭터 등록과 수정은 이름만 입력합니다. 기존 월드·직업 정보는 유지하며 신규 캐릭터는 API 조회 전까지 미확인으로 표시합니다. 월드가 확인된 캐릭터끼리만 동일 월드 여부를 검사하고, 미확인 캐릭터가 있는 파티에는 확인 안내를 표시합니다. 명령어 변경 후 `./run.command register`를 다시 실행하세요.

- 일반 텍스트 채널에서도 `/보스방 시작`으로 사용합니다. 채널마다 캐릭터·파티 목록은 독립적입니다. 기존 스레드 데이터는 유지합니다.
- 일반 채널의 참가 기준은 채널 보기·메시지 보내기 권한입니다. 관리자는 채널 관리 권한을 사용합니다. 스레드는 기존 참가·관리 기준을 유지합니다.
- 공용 관리판과 `/캐릭터 목록`, `/파티 목록`, `/파티 정보`는 모두에게 보입니다. 공개 조회 카드는 조회 시점의 상태이며 버튼으로 최신 개인 관리 화면을 엽니다.
- 개인 화면의 보스방·캐릭터·파티 이동 및 모달 제출은 기존 메시지를 갱신합니다. 공용 카드에서 새로 시작하거나 별도 명령을 실행하면 개인 화면이 새로 열릴 수 있습니다.
- 웹 개발은 보류합니다. 서비스·저장소·Discord 처리를 분리하여 추후 API를 연결할 수 있게 유지합니다. 현재 외부 HTTP API는 개방하지 않습니다.
- 적용하려면 봇을 재시작하세요. 일반 채널에 필요한 **메시지 보내기** 권한이 없으면 `./run.command invite`로 설치 권한을 갱신하거나 채널 권한을 설정하세요.

- 스레드별 보스방 시작 및 관리판 게시·갱신.
- 각 참가자의 본캐·부캐 다중 등록, 목록, 수정, 등록 해제. 등록 개수 제한 없음.
- 스레드 참가자들이 등록한 캐릭터로 파티 생성·편성·제외.
- 같은 캐릭터를 서로 다른 파티에서 사용 가능. 한 파티에서는 한 사람당 캐릭터 하나.
- 파티마다 독립적인 보스·난이도 목록.
- 파티 복사, 이름 변경, 보관·복원.
- 등록 캐릭터·파티가 많아도 페이지 이동과 자동완성 검색으로 접근.
- SQLite 저장, 중복 요청 방지, 오래된 편집 버튼 감지.
- 재시작 후에도 기존 관리판 버튼 동작. 스레드 삭제가 DB를 삭제하지 않음.

캐릭터는 **이름만 등록**합니다. 선택적으로 넥슨 API를 연결하면 월드·직업과 스펙을 자동 수집합니다. 닉네임 등록과 API 조회는 소유 인증이 아닙니다. 회차·일정·클리어·수익 정산과 웹 연동은 후속 단계입니다.

## 구조

Linux 서버 자동 배포 파일을 추가했습니다. 최초 서버 준비와 GitHub 연결은 [자동 배포 안내](deploy/README.md)를 참고하세요. 실제 원격 연결은 아직 설정하지 않았습니다.

```text
디스코드 서버
└─ 스레드: 목요일 보스방
   ├─ 도토리의 캐릭터: 본캐 A, 부캐 B, 부캐 C …
   ├─ 모찌의 캐릭터: 본캐 D, 부캐 E …
   ├─ 파티 1: A + D → 하드 세렌, 노말 칼로스
   └─ 파티 2: B + E → 하드 스우, 하드 데미안
```

## 이 컴퓨터에서 실행하기

현재 프로젝트에는 의존성을 설치해 두었습니다. `run.command`는 설치된 Node.js 또는 Codex에 포함된 Node.js 런타임을 찾아 사용합니다. 다른 컴퓨터에는 **Node.js 24 이상**, 패키지 설치용 **pnpm**이 필요합니다. 패키지는 `pnpm-lock.yaml`에 고정되어 있습니다.

1. [Discord Developer Portal](https://discord.com/developers/applications)에서 새 애플리케이션을 만들고 Bot 항목에서 토큰을 발급합니다.
2. General Information의 Application ID와 사용할 디스코드 서버 ID를 복사합니다. 서버 ID 복사는 디스코드의 개발자 모드를 켠 뒤 가능합니다.
3. 아래처럼 `.env` 파일을 만들고 직접 세 값을 입력합니다. **봇 토큰을 채팅으로 보내지 말고 로컬 `.env`에만 넣으세요.**

```sh
test -f .env || cp .env.example .env
```

```dotenv
DISCORD_TOKEN=발급한_봇_토큰
DISCORD_APPLICATION_ID=앱_ID
DISCORD_GUILD_ID=테스트_서버_ID
DATABASE_PATH=./data/bot.sqlite
```

4. 처음 내려받은 소스라면 의존성을 설치합니다. 이 작업 공간에는 이미 설치되어 있습니다.

```sh
./run.command install
```

5. 먼저 초대 링크를 생성하고, 링크를 열어 대상 서버에 앱을 승인합니다. 이 명령은 네트워크 요청 없이 링크만 출력합니다.

```sh
./run.command invite
```

그다음 명령어를 테스트 서버에 등록합니다.

```sh
./run.command register
```

등록 스크립트는 해당 앱의 테스트 서버 명령어 목록을 이 프로젝트 정의로 교체하므로 새 봇 애플리케이션 사용을 권장합니다. 등록 실패 시 HTTP 상태와 Discord API 코드를 표시합니다.

6. 봇을 실행합니다.

```sh
./run.command start
```

`봇 연결 완료` 로그가 나오면 실행 중입니다. 종료는 `Ctrl+C`입니다. 컴퓨터가 잠자기에 들어가거나 프로세스가 종료되면 봇은 오프라인이 됩니다.

Node.js와 pnpm이 일반 경로에 있으면 `pnpm register`, `pnpm start`, `pnpm test`도 사용할 수 있습니다.

## 디스코드에서 처음 사용하기

환경 설정과 등록 오류는 [설정·등록 오류 안내](SETUP.md)를 참고하세요.

1. 사용할 서버에서 일반 텍스트 스레드 또는 포럼 게시물을 만듭니다. 비공개 스레드라면 봇도 초대해 주세요.
2. 각 사용자가 스레드에 참여합니다. 읽을 수 있는 것과 스레드 참가 상태는 구분해 확인합니다.
3. 스레드 안에서 `/보스방 시작`을 실행합니다.
4. 참가자가 각자 `내 캐릭터 등록` 버튼으로 원하는 만큼 등록합니다.
5. `파티 만들기` 버튼으로 파티를 만듭니다.
6. `캐릭터 추가`로 스레드 목록에서 선택하고 `보스 추가`로 보스와 난이도를 등록합니다.

대표 명령어:

```text
/보스방 시작
/캐릭터 등록 이름:도토리검사
/캐릭터 등록 이름:도토리마법사
/캐릭터 목록
/파티 생성 이름:목요일 본캐팟
/파티 정보 파티:목요일 본캐팟
/파티 캐릭터추가 파티:목요일 본캐팟 캐릭터:도토리검사
/파티 보스추가 파티:목요일 본캐팟 보스:선택받은 세렌 난이도:하드
/파티 복사 파티:목요일 본캐팟 이름:부캐팟
```

명령어의 파티·캐릭터 항목은 **자동완성 후보를 선택**합니다. 텍스트로 이름만 입력하면 내부 ID가 없으므로 조회에 실패할 수 있습니다. 후보가 많으면 이름을 입력해 검색하세요.

봇의 관리 버튼은 개인에게만 보이는 편집 창을 열고, 저장이 끝나면 스레드의 공용 관리판을 갱신합니다. 봇 재시작 이후에도 관리판을 계속 사용할 수 있습니다.

## 권한과 편성 규칙

- 스레드 참가자만 명령을 사용합니다. 참가 여부는 요청 시 디스코드 API로 확인합니다.
- 캐릭터의 수정·등록 해제는 본인만 가능합니다.
- 모든 참가자는 파티를 만들고 현재 스레드의 캐릭터 목록을 볼 수 있습니다.
- 파티 편집은 생성자 또는 `스레드 관리` 권한이 있는 참가자가 할 수 있습니다.
- 다른 사람의 파티도 복사할 수 있으며 복사본은 본인이 관리합니다.
- 한 파티 안에서는 같은 사용자의 두 캐릭터를 동시에 편성하지 않습니다. 첫 버전은 같은 월드로 편성합니다.
- 같은 캐릭터·월드의 중복 등록을 막습니다. 등록자는 본인 소유임을 선언하며 게임 계정 소유 인증은 추후 연결합니다.
- 참가자가 스레드를 나가면 새 편성에서 제외합니다. 기존 파티에서 해당 캐릭터를 제외하는 작업은 가능합니다.
- 같은 캐릭터의 보스가 여러 파티에 겹치면 확인 문구를 표시합니다. 실제 보상 주기·난이도 공유 제한 계산은 아직 하지 않습니다.
- 활성 파티에 편성된 캐릭터는 먼저 파티에서 제외한 뒤 등록 해제하거나 이름·월드를 바꿉니다.
- 보관한 파티는 복원할 수 있습니다. 그 사이 캐릭터 등록이 해제됐다면 복사 기능으로 사용 가능한 구성만 옮겨 주세요.

봇에 필요한 채널 권한: `채널 보기`, `스레드에서 메시지 보내기`, `메시지 기록 보기`, `링크 임베드`.
관리자 권한은 요구하지 않습니다. Message Content Intent와 Server Members Intent도 사용하지 않습니다. 이 봇은 기존 스레드에서 작동하므로 스레드 생성 권한을 요구하지 않습니다. Gateway로 연결하므로 별도의 Interactions Endpoint URL을 설정하지 않습니다.

## 초기 보스 목록

세렌, 칼로스, 카링, 림보, 검은 마법사, 스우, 데미안, 윌을 `src/catalog.js`에 정의했습니다. 현재 목록은 첫 구현용이며 전체 보스 목록은 아닙니다. 보스를 추가하거나 난이도를 변경한 뒤에는 `/파티 보스추가` 명령의 선택지를 반영하도록 `./run.command register`를 다시 실행합니다.

보스 목록은 실제 게임 업데이트와 대조해 유지해야 하며, 가격·보상 주기·최대 파티 인원은 이 카탈로그에서 가정하지 않습니다.

## 데이터와 백업

기본 DB는 `data/bot.sqlite`입니다. 사용자 ID·스레드 ID·직접 등록한 캐릭터·파티·보스 목록을 저장합니다. DB 경로를 영구 디스크에 두고 한 봇 프로세스로 실행하세요. 웹을 함께 운영하거나 여러 인스턴스로 확장할 때 PostgreSQL 저장 어댑터로 전환하는 것을 권장합니다.

실행 중인 SQLite도 안전하게 백업할 수 있습니다.

```sh
./run.command backup
```

백업은 `data/backups/`에 새 파일로 생성됩니다. 복원할 때는 봇을 종료한 뒤 기존 DB와 `-wal`·`-shm` 파일을 별도 보관하고, 백업 파일을 `DATABASE_PATH` 위치에 복사한 뒤 다시 실행합니다. 실행 중인 DB 파일만 단순 복사하는 방식은 사용하지 마세요.

토큰은 DB에 저장하지 않습니다. `.env`, `data/`, 의존성 폴더는 소스 배포에서 제외합니다.

## 검증

```sh
./run.command check
./run.command test
```

테스트는 로컬 DB와 디스코드 상호작용 모형을 사용하며, 실제 디스코드에 메시지를 보내지 않습니다. 권한, 스레드 분리, 등록 개수, 중복 요청, 파티 편성, 보스 목록, 버튼 버전, 재시작 유지와 Discord UI 크기 제한을 검증합니다.

2026-11-11 로컬 검증 결과: **28개 테스트 통과**, 명령어·UI 스키마 확인 통과. 실행 중 DB의 백업·복원 조회도 검증했습니다.

**실제 서버 로그인·초대·명령 등록·메시지 송수신 검증은 봇 인증 정보 설정 후 진행해야 합니다.** 현재 작업에서는 실제 인증 정보를 제공받거나 디스코드에 연결하지 않았습니다.

## 소스 구조

| 파일 | 역할 |
|---|---|
| `src/bot.js` | Gateway 연결과 실행 |
| `src/commands.js` | 슬래시 명령어 정의 |
| `src/access.js` | 실제 스레드 참가자·권한 확인 |
| `src/interactions.js` | 명령·버튼·모달 처리 |
| `src/views.js` | 관리판·목록·편성 메뉴 |
| `src/service.js` | 캐릭터·파티·보스 관리 규칙 |
| `src/repository.js` | SQLite 트랜잭션·영구 저장·중복 방지 |
| `src/board.js` | 공용 관리판 갱신·재생성 |
| `src/catalog.js` | 초기 보스·난이도 목록 |

웹 연결 시 사용자·스레드 권한은 웹 서버에서도 검증해야 합니다. `service.js`의 사용자 문맥은 외부 입력을 그대로 전달하지 않고 인증된 서버 코드에서 구성하는 전제입니다.

## 스펙 자동 추적

서버 `.env`에 메이플스토리용 `NEXON_API_KEY`를 설정하면 활성 등록 캐릭터의 스펙을 자동 수집합니다. 키는 채팅이나 Git에 올리지 않습니다. 기본 정보 API로 월드·직업·이름을 갱신하며, API로 연결한 캐릭터의 닉네임 변경은 식별자를 통해 자동 반영합니다. 다른 캐릭터로 바꾸려면 새로 등록하세요.

- **수집 시점:** 등록 직후, 봇 시작 시, 이후 매시간 미수집 캐릭터 확인. 캐릭터마다 한국 날짜 기준 하루 한 번 성공한 기록을 저장합니다. 봇이 꺼진 기간의 과거 기록을 자동으로 채우지는 않습니다.
- **직접 갱신:** `/캐릭터 스펙갱신 캐릭터:...` 또는 스펙 카드의 `스펙 갱신`. 본인 캐릭터만 갱신 가능하며, 10분 이내 재요청은 저장된 결과를 표시합니다.
- **조회:** 캐릭터 목록의 `스펙 변화` 또는 `/캐릭터 스펙 캐릭터:...`. 이전 기록·다음 변화 버튼으로 이력을 탐색합니다. 현재 공간의 참가자가 조회할 수 있는 개인 응답입니다.
- **추적:** 캐릭터 레벨, 전투력, 현재 착용 장비의 교체·스타포스·잠재·에디셔널·옵션 변경, 차수별 스킬 레벨과 V/HEXA 코어 레벨. 장비 프리셋 변경은 별도로 표시합니다. 미착용 프리셋 전체·캐시 장비·심볼·유니온·HEXA 스탯은 이 버전의 수집 범위가 아닙니다.
- **비교 기준:** 수집한 최신 API 응답을 이전 수집과 비교합니다. 각 엔드포인트가 단일 시각의 원자적 스냅샷인 것은 아닙니다. 버프·장비 세팅 변화도 수치 변화에 포함됩니다. 스킬 미제공 구간은 삭제나 레벨 0으로 간주하지 않습니다.
- **보관:** API 스펙 스냅샷은 최근 29일, 조회 화면은 최신 100건입니다. 이전 스냅샷은 정리합니다. 수동 환산 기록은 별도로 유지합니다. 장기 API 이력 보관은 공식 갱신 조건을 충족하는 재조회 설계 후 확장합니다.
- **호출량:** 프로세스 전체 요청을 직렬화하고 요청 간 250ms 간격·10초 타임아웃을 둡니다. 개발 단계 키를 고려해 이 봇의 하루 호출 예산은 900회이며 DB에 기록해 재시작해도 유지합니다. 같은 키를 다른 서비스에서 사용한 호출량은 알 수 없습니다. 고레벨 캐릭터 최초 수집은 약 15~17회 요청이 필요합니다.
- **장애:** 필수 정보 조회 실패 시 새 스냅샷을 저장하지 않습니다. 자동 수집 실패는 다음 점검에서 다시 시도하며 기존 이력은 유지합니다. 현재 채널/스레드 참가 자격이 없는 등록자는 자동 수집에서 건너뜁니다.
- **월드 확인:** API 결과로 기존 파티의 월드가 서로 달라진 경우 구성을 지우지 않고 경고합니다. 이후 편성과 복원에는 확인된 월드 검사를 적용합니다.

### 환산

Maple Scouter의 공개 약관 제15조는 자동화된 접근 및 다른 도구의 데이터 소스로 사용하는 행위를 금지합니다. 허용된 연동 경로가 확보되기 전에는 자동 수집하지 않습니다. 사이트를 직접 열어 확인한 값은 아래 명령으로 기록할 수 있습니다.

```text
/캐릭터 환산기록 캐릭터:도토리검사 수치:65000 종류:헥사
/캐릭터 환산기록 캐릭터:도토리검사 수치:50000 종류:주스탯
```

`6.5`가 아니라 `65000`처럼 표시된 수치를 입력합니다. 본인만 기록할 수 있으며, 주스탯과 헥사를 구분하고 기록 시각과 직전 동종 기록 대비 증감을 표시합니다. API 자동 수집값으로 표시하지 않습니다.

### 적용과 검증

1. 서버 `shared/.env`에 `NEXON_API_KEY`를 추가합니다. 키가 없어도 이름 등록과 기존 파티 기능은 사용할 수 있습니다.
2. 변경 소스를 배포하고 봇을 재시작합니다.
3. 자동 배포에서는 Discord 명령어도 자동 등록됩니다. 수동 실행 환경에서는 명령 정의가 바뀌면 `node scripts/register.js`를 실행합니다. Docker 환경의 정확한 명령은 [배포 안내](deploy/README.md)를 따릅니다.
4. 캐릭터 한 개를 등록하거나 `스펙갱신`한 뒤 월드·직업·전투력·장비·스킬을 확인합니다.
