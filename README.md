# 메이플 스레드 보스봇 — 첫 구현

**일반 채널 또는 스레드에서 개인 API 키로 캐릭터를 불러오고, 여러 파티와 보스·스펙·스케줄러를 관리하는 Discord 봇입니다.** 웹 사이트 없이 실행합니다.

## 현재 구현된 범위

### 2026-11-13 변경 사항 (아래 이전 설명보다 우선)

- 보스 기록(스케줄러 캐시 기반 조회·저장), 결정석 가격표·파티 1인 수익, 분배금 계산·수정 로그를 추가했습니다. [보스 기록 · 결정석 수익 · 분배금](#보스-기록--결정석-수익--분배금)을 참고하세요. 명령어가 늘었으므로 `./run.command register`를 다시 실행하세요.
- 실제 스케줄러 API의 날짜 형식(`2026-11-11T00:00+09:00`) 때문에 스케줄러 수집이 실패하던 문제를 수정했습니다.

- 신규 캐릭터 등록은 개인 API 키 연결로 대체했습니다. 월드·직업은 자동으로 가져옵니다. 기존 수동 등록 캐릭터는 유지합니다. 개인 키 암호화 설정과 명령어 재등록이 필요합니다. 자세한 사용법은 아래 개인 API 키 연결 항목을 확인하세요.

- 일반 텍스트 채널에서도 `/보스방 시작`으로 사용합니다. 채널마다 캐릭터·파티 목록은 독립적입니다. 기존 스레드 데이터는 유지합니다.
- 일반 채널의 참가 기준은 채널 보기·메시지 보내기 권한입니다. 관리자는 채널 관리 권한을 사용합니다. 스레드는 기존 참가·관리 기준을 유지합니다.
- 공용 관리판과 `/캐릭터 목록`, `/파티 목록`, `/파티 정보`는 모두에게 보입니다. 공개 조회 카드는 조회 시점의 상태이며 버튼으로 최신 개인 관리 화면을 엽니다.
- 개인 화면의 보스방·캐릭터·파티 이동 및 모달 제출은 기존 메시지를 갱신합니다. 공용 카드에서 새로 시작하거나 별도 명령을 실행하면 개인 화면이 새로 열릴 수 있습니다.
- 웹 개발은 보류합니다. 서비스·저장소·Discord 처리를 분리하여 추후 API를 연결할 수 있게 유지합니다. 현재 외부 HTTP API는 개방하지 않습니다.
- 적용하려면 봇을 재시작하세요. 일반 채널에 필요한 **메시지 보내기** 권한이 없으면 `./run.command invite`로 설치 권한을 갱신하거나 채널 권한을 설정하세요.

- 스레드별 보스방 시작 및 관리판 게시·갱신.
- 각 참가자의 본캐·부캐 다중 등록, 목록, 수정, 등록 해제. 등록 개수 제한 없음.
- 스레드 참가자들이 등록한 캐릭터로 파티 생성·편성·제외.
- 같은 캐릭터를 서로 다른 파티에서 사용 가능. 한 파티에서는 한 사람당 캐릭터 하나.
- 파티마다 독립적인 보스·난이도 목록.
- 파티 복사, 이름 변경, 보관·복원.
- 등록 캐릭터·파티가 많아도 페이지 이동과 자동완성 검색으로 접근.
- SQLite 저장, 중복 요청 방지, 오래된 편집 버튼 감지.
- 재시작 후에도 기존 관리판 버튼 동작. 스레드 삭제가 DB를 삭제하지 않음.

캐릭터는 **개인 API 키로 일괄 등록**합니다. 키의 계정 캐릭터 목록을 기준으로 연결하며, 기존 수동 등록 캐릭터는 별도로 유지합니다. 회차·일정·클리어·수익 정산과 웹 연동은 후속 단계입니다.

## 구조

Linux 서버 자동 배포 파일을 추가했습니다. 최초 서버 준비와 GitHub 연결은 [자동 배포 안내](deploy/README.md)를 참고하세요. 실제 원격 연결은 아직 설정하지 않았습니다.

```text
디스코드 서버
└─ 스레드: 목요일 보스방
   ├─ 도토리의 캐릭터: 본캐 A, 부캐 B, 부캐 C …
   ├─ 모찌의 캐릭터: 본캐 D, 부캐 E …
   ├─ 파티 1: A + D → 하드 세렌, 노말 칼로스
   └─ 파티 2: B + E → 하드 스우, 하드 데미안
```

## 이 컴퓨터에서 실행하기

현재 프로젝트에는 의존성을 설치해 두었습니다. `run.command`는 설치된 Node.js 또는 Codex에 포함된 Node.js 런타임을 찾아 사용합니다. 다른 컴퓨터에는 **Node.js 24 이상**, 패키지 설치용 **pnpm**이 필요합니다. 패키지는 `pnpm-lock.yaml`에 고정되어 있습니다.

1. [Discord Developer Portal](https://discord.com/developers/applications)에서 새 애플리케이션을 만들고 Bot 항목에서 토큰을 발급합니다.
2. General Information의 Application ID와 사용할 디스코드 서버 ID를 복사합니다. 서버 ID 복사는 디스코드의 개발자 모드를 켠 뒤 가능합니다.
3. 아래처럼 `.env` 파일을 만들고 직접 세 값을 입력합니다. **봇 토큰을 채팅으로 보내지 말고 로컬 `.env`에만 넣으세요.**

```sh
test -f .env || cp .env.example .env
```

```dotenv
DISCORD_TOKEN=발급한_봇_토큰
DISCORD_APPLICATION_ID=앱_ID
DISCORD_GUILD_ID=테스트_서버_ID
DATABASE_PATH=./data/bot.sqlite
```

4. 처음 내려받은 소스라면 의존성을 설치합니다. 이 작업 공간에는 이미 설치되어 있습니다.

```sh
./run.command install
```

5. 먼저 초대 링크를 생성하고, 링크를 열어 대상 서버에 앱을 승인합니다. 이 명령은 네트워크 요청 없이 링크만 출력합니다.

```sh
./run.command invite
```

그다음 명령어를 테스트 서버에 등록합니다.

```sh
./run.command register
```

등록 스크립트는 해당 앱의 테스트 서버 명령어 목록을 이 프로젝트 정의로 교체하므로 새 봇 애플리케이션 사용을 권장합니다. 등록 실패 시 HTTP 상태와 Discord API 코드를 표시합니다.

6. 봇을 실행합니다.

```sh
./run.command start
```

`봇 연결 완료` 로그가 나오면 실행 중입니다. 종료는 `Ctrl+C`입니다. 컴퓨터가 잠자기에 들어가거나 프로세스가 종료되면 봇은 오프라인이 됩니다.

Node.js와 pnpm이 일반 경로에 있으면 `pnpm register`, `pnpm start`, `pnpm test`도 사용할 수 있습니다.

## 디스코드에서 처음 사용하기

환경 설정과 등록 오류는 [설정·등록 오류 안내](SETUP.md)를 참고하세요.

1. 사용할 서버에서 일반 텍스트 스레드 또는 포럼 게시물을 만듭니다. 비공개 스레드라면 봇도 초대해 주세요.
2. 각 사용자가 스레드에 참여합니다. 읽을 수 있는 것과 스레드 참가 상태는 구분해 확인합니다.
3. 스레드 안에서 `/보스방 시작`을 실행합니다.
4. 참가자가 각자 `내 API 키 연결` 버튼으로 계정 캐릭터를 불러옵니다.
5. `파티 만들기` 버튼으로 파티를 만듭니다.
6. `캐릭터 추가`로 스레드 목록에서 선택하고 `보스 추가`로 보스와 난이도를 등록합니다.

대표 명령어:

```text
/보스방 시작
/캐릭터 연결
/캐릭터 동기화
/캐릭터 목록
/파티 생성 이름:목요일 본캐팟
/파티 정보 파티:목요일 본캐팟
/파티 캐릭터추가 파티:목요일 본캐팟 캐릭터:도토리검사
/파티 보스추가 파티:목요일 본캐팟 보스:선택받은 세렌 난이도:하드
/파티 복사 파티:목요일 본캐팟 이름:부캐팟
```

명령어의 파티·캐릭터 항목은 **자동완성 후보를 선택**합니다. 텍스트로 이름만 입력하면 내부 ID가 없으므로 조회에 실패할 수 있습니다. 후보가 많으면 이름을 입력해 검색하세요.

봇의 관리 버튼은 개인에게만 보이는 편집 창을 열고, 저장이 끝나면 스레드의 공용 관리판을 갱신합니다. 봇 재시작 이후에도 관리판을 계속 사용할 수 있습니다.

## 권한과 편성 규칙

- 스레드 참가자만 명령을 사용합니다. 참가 여부는 요청 시 디스코드 API로 확인합니다.
- 캐릭터의 수정·등록 해제는 본인만 가능합니다.
- 모든 참가자는 파티를 만들고 현재 스레드의 캐릭터 목록을 볼 수 있습니다.
- 파티 편집은 생성자 또는 `스레드 관리` 권한이 있는 참가자가 할 수 있습니다.
- 다른 사람의 파티도 복사할 수 있으며 복사본은 본인이 관리합니다.
- 한 파티 안에서는 같은 사용자의 두 캐릭터를 동시에 편성하지 않습니다. 첫 버전은 같은 월드로 편성합니다.
- 같은 캐릭터·월드의 중복 등록을 막습니다. 등록자는 본인 소유임을 선언하며 기존 수동 등록은 소유 인증 상태로 간주하지 않습니다.
- 참가자가 스레드를 나가면 새 편성에서 제외합니다. 기존 파티에서 해당 캐릭터를 제외하는 작업은 가능합니다.
- 같은 캐릭터의 보스가 여러 파티에 겹치면 확인 문구를 표시합니다. 실제 보상 주기·난이도 공유 제한 계산은 아직 하지 않습니다.
- 활성 파티에 편성된 캐릭터는 먼저 파티에서 제외한 뒤 등록 해제하거나 이름·월드를 바꿉니다.
- 보관한 파티는 복원할 수 있습니다. 그 사이 캐릭터 등록이 해제됐다면 복사 기능으로 사용 가능한 구성만 옮겨 주세요.

봇에 필요한 채널 권한: `채널 보기`, `스레드에서 메시지 보내기`, `메시지 기록 보기`, `링크 임베드`.
관리자 권한은 요구하지 않습니다. Message Content Intent와 Server Members Intent도 사용하지 않습니다. 이 봇은 기존 스레드에서 작동하므로 스레드 생성 권한을 요구하지 않습니다. Gateway로 연결하므로 별도의 Interactions Endpoint URL을 설정하지 않습니다.

## 보스 목록

하드 스우부터 익스트림 발드릭스까지 결정석 가격이 있는 보스 18종을 `src/catalog.js`에 정의했습니다: 스우, 데미안, 가디언 엔젤 슬라임, 루시드, 윌, 더스크, 진 힐라, 듄켈, 검은 마법사(월간), 선택받은 세렌, 감시자 칼로스, 최초의 대적자, 카링, 찬란한 흉성, 림보, 발드릭스, 유피테르, 벨로나. 보스를 추가하거나 난이도를 변경한 뒤에는 `/파티 보스추가`·`/결정석 가격수정` 선택지를 반영하도록 `./run.command register`를 다시 실행합니다.

보스마다 결정석 수익을 나눌 최대 인원(`maxParty`)을 두고, 난이도별 예외는 `partyLimits`로 지정합니다. 최초의 대적자·찬란한 흉성·림보·발드릭스·유피테르·벨로나는 3인, 감시자 칼로스·카링(전 난이도)과 검밑솔·세렌·검은 마법사는 6인, 익스트림 스우는 2인입니다. 노말 진 힐라 이하 보스는 솔플로 가정해 가격을 두지 않습니다. 보스 목록과 가격은 실제 게임 업데이트와 대조해 유지해야 합니다.

## 보스 기록 · 결정석 수익 · 분배금

### 보스 기록 (스케줄러 캐시)

별도 키를 받지 않고 `/캐릭터 연결`로 저장한 개인 API 연결과, 매시간 자동 수집하는 스케줄러 스냅샷(`scheduler_snapshots`)을 그대로 사용합니다.

- `/보스기록 조회 캐릭터 주차:(이번 주|지난주)`: **캐시를 먼저 보여 줍니다.** 해당 주차 캐시가 없을 때만 API를 1회 호출합니다. 화면에 수집 시각을 표시합니다.
- `갱신` 버튼: 등록자의 키로 다시 조회합니다.
  - 이번 주: 기존 스케줄러 갱신과 같이 5분 이내 수집분이 있으면 호출하지 않습니다.
  - 지난주: 초기화 직전 수요일을 `date`로 1회 조회해 **확정 기록**으로 표시하고, 이후 갱신은 호출하지 않습니다. 자동 수집이 수요일 낮에 남긴 스냅샷은 확정이 아니므로 갱신하면 다시 조회합니다.
- `예`/`아니오`: 화면에 보인 기록을 그대로 `boss_history`에 저장합니다. 그 사이 캐시가 바뀌었으면 다시 확인하라고 안내합니다. 같은 주차는 마지막 저장으로 바뀌고, API 보관 기간(14일)과 상관없이 누적됩니다.
- `/보스기록 히스토리 캐릭터`: 저장한 주차별 기록을 최신순으로 봅니다.
- **조회 권한:** 본인 캐릭터, 또는 같은 활성 파티에 캐릭터가 편성된 파티원의 캐릭터. 다른 파티원의 기록은 **보스 클리어 요약만** 보이며(일일·주간 전체 스케줄러는 계속 본인 전용), 조회하거나 API로 갱신할 때 대상자를 **@mention**합니다. 캐시로만 다시 본 경우에는 알리지 않습니다.
- **호출량:** 계정 캐릭터 목록을 다시 부르지 않고 연결에 저장된 ocid를 사용합니다. 같은 키의 요청은 기존 연결의 직렬화 큐와 키별 하루 예산을 함께 씁니다.

### 결정석 수익

- `/결정석 가격표`: 현재 서버의 가격표. 초기값은 기획 문서의 가격(검밑솔~그란디스 최상위 39항목)을 따릅니다.
- `/결정석 가격수정 보스 난이도 가격`: 서버 단위로 가격을 덮어씁니다. `4억 6500만`, `465000000`, `1,230,000,000` 형식을 받습니다.
- 파티 정보에 **결정석 수익 · 1인 기준**을 표시합니다. 1인 수익 = 결정석 가격 ÷ min(파티 캐릭터 수, 보스·난이도 최대 인원). 월간 보스는 주간 합계와 따로 표시합니다.

### 분배금

파티 정보의 `분배금 계산` 버튼 또는 `/분배 시작 파티`로 시작합니다.

1. "분배할 아이템이 있나요?" → **아니오**를 누르면 진행하지 않습니다.
2. **예** → 판매자를 @선택합니다. 파티에 캐릭터가 편성된 사람만 가능하며, 아니면 "해당 파티의 인원이 아닙니다."를 표시합니다.
3. 거래 품목과 거래금(경매장 판매 금액)을 입력하면 채널에 결과 카드를 게시합니다.

| 항목 | 계산 |
|---|---|
| 판매자 실수령액 | 거래금 × 0.95 |
| MVP 할인가(실수령) | 거래금 × 0.97 |
| 최종 수령 금액 | (실수령액 ÷ n) × 0.95 |
| MVP 할인가(최종) | (MVP 실수령액 ÷ n) × 0.97 |

n은 판매자를 포함한 파티원 수입니다. 기록 시점의 파티 캐릭터 수로 시작하며 수정 화면에서 1~6 사이로 바꿀 수 있습니다. 금액은 메소 단위로 내림합니다. 결과 카드의 `MVP 할인 적용` 버튼을 켜면 MVP 줄을 함께 표시하고, 카드 아래 **계산식** 칸에 각 금액의 식을 따로 적습니다. 품목·거래금·파티원 수 수정과 MVP 할인 전환은 **판매자만** 할 수 있고, 변경 전후 값을 `distribution_edits` 테이블에 로그로 남깁니다. `/분배 목록 파티`로 지난 기록을 다시 열 수 있습니다.

## 데이터와 백업

기본 DB는 `data/bot.sqlite`입니다. 사용자 ID·스레드 ID·직접 등록한 캐릭터·파티·보스 목록을 저장합니다. DB 경로를 영구 디스크에 두고 한 봇 프로세스로 실행하세요. 웹을 함께 운영하거나 여러 인스턴스로 확장할 때 PostgreSQL 저장 어댑터로 전환하는 것을 권장합니다.

실행 중인 SQLite도 안전하게 백업할 수 있습니다.

```sh
./run.command backup
```

백업은 `data/backups/`에 새 파일로 생성됩니다. 복원할 때는 봇을 종료한 뒤 기존 DB와 `-wal`·`-shm` 파일을 별도 보관하고, 백업 파일을 `DATABASE_PATH` 위치에 복사한 뒤 다시 실행합니다. 실행 중인 DB 파일만 단순 복사하는 방식은 사용하지 마세요.

Discord 봇 토큰은 DB에 저장하지 않습니다. 개인 넥슨 API 키는 서버 암호화 키로 암호화해 저장합니다. `.env`, `data/`, 의존성 폴더는 소스 배포에서 제외합니다.

## 개인 API 키 연결과 자동 추적

캐릭터 이름을 하나씩 입력하는 대신, **각 참가자가 자신의 메이플스토리 API 키를 연결**합니다. 현재 보스방에 API가 반환하는 모든 계정 캐릭터를 불러옵니다. 서버 공용 `NEXON_API_KEY`는 사용하지 않습니다.

### 서버 준비

`shared/.env`(로컬 실행은 `.env`)에 `API_KEY_ENCRYPTION_KEY`를 한 번 설정해야 합니다. 다음 명령으로 32바이트 무작위 값을 생성하고 출력된 값을 서버 설정 파일에 저장하세요.

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"
```

이 값은 **개인 API 키를 암호화하는 서버 비밀값**이며 넥슨에서 발급받는 개인 키와 다릅니다. Git·채팅에 올리지 말고 재배포에도 유지하세요. DB 복원 시에도 동일한 암호화 키가 필요합니다. 키를 잃거나 바꾸면 저장된 개인 키를 복호화할 수 없습니다.

배포·봇 재시작 후 명령어 정의를 다시 등록합니다. Docker에서는 [배포 안내](deploy/README.md)의 `node scripts/register.js` 실행 방법을 따릅니다.

### 사용자 흐름

1. 현재 채널/스레드에서 `/보스방 시작`.
2. `내 API 키 연결` 또는 `/캐릭터 연결`.
3. 안내를 확인하고 `API 키 입력` 버튼의 Discord 입력창에 **본인 메이플스토리용 API 키** 입력. 일반 채팅이나 슬래시 명령 옵션에 키를 넣지 않습니다.
4. 키를 검증한 뒤 캐릭터 이름·월드·직업을 현재 보스방에 일괄 등록합니다. 목록은 해당 공간의 다른 참가자에게도 보이며 다른 보스방에는 자동 공유하지 않습니다.
5. 캐릭터 목록에서 파티를 편성하고 `스펙 변화` 또는 `내 스케줄러`를 엽니다.

키는 사용자·서버·채널/스레드 범위별로 AES-256-GCM 암호화 저장합니다. 개인 캐릭터 식별자도 암호화하며, 키를 응답·로그·요청 영수증에 기록하지 않습니다. Discord 입력창의 키 입력 자체는 Discord를 통해 봇에 전달됩니다.

- `/캐릭터 동기화`: 본인 계정 목록 재조회. 1분 이내에는 기존 결과를 사용합니다. 자동 목록 갱신은 6시간 간격입니다.
- `/캐릭터 연결`: 상태 확인 및 키 교체. 새 키 검증에 실패하면 기존 연결을 유지합니다.
- `/캐릭터 연결해제`: 확인 후 이 공간의 저장된 키·API 연결 정보를 삭제하고 자동 추적을 중단합니다. 기존 캐릭터·파티·이력은 보존합니다. 키 재발급/폐기는 넥슨에서 별도로 할 수 있습니다.
- 기존 본인 캐릭터는 식별자 또는 동일 이름·월드가 일치하면 기존 ID에 연결해 파티·이력을 유지합니다. 다른 사람의 등록과 충돌하면 건너뛰고 개수를 안내합니다.
- API 목록에서 사라진 캐릭터는 자동 추적만 중단하며 파티 구성을 삭제하지 않습니다. 기존 `/캐릭터 해제`로 제외한 캐릭터는 동기화만으로 재활성화하지 않습니다.

### 스펙 변화

- `/캐릭터 스펙`: 장비 교체·스타포스·잠재·에디셔널·옵션, 스킬·V/HEXA 코어 레벨, 전투력·캐릭터 레벨 비교.
- `/캐릭터 스펙갱신`: 본인 캐릭터를 직접 갱신. 스펙 카드의 `스펙 확인` 버튼도 매번 API를 다시 조회합니다. 프리셋을 검사하거나 조회를 제한하지 않습니다. 진행 중인 중복 요청은 하나로 합칩니다. API 반영 지연 때문에 재조회해도 같은 값일 수 있습니다.
- 자동 수집은 봇 시작·키 연결·매시간 점검 시 실행하며 캐릭터마다 한국 날짜 기준 하루 한 번 성공한 기록을 저장합니다.
- API 스펙 이력은 **최근 29일**, 화면에서는 최신 100건까지 조회합니다. 스펙 조회는 같은 공간의 참가자에게 허용됩니다.
- 현재 착용 장비·적용 중인 스킬/코어가 대상입니다. 미착용 프리셋 전체·캐시 장비·심볼·유니온·HEXA 스탯은 수집 범위가 아닙니다.
- 버프·세팅·프리셋 변경도 수치 변화에 포함됩니다. 여러 엔드포인트가 정확히 동일 시각을 보장하지는 않습니다. 미제공 스킬 구간을 삭제/레벨 0으로 처리하지 않습니다.
- API로 확인된 월드가 기존 파티와 다르면 슬롯을 지우지 않고 경고합니다.

### 스케줄러 추적

- `/캐릭터 스케줄러`: **본인 캐릭터만** 일일·주간 콘텐츠, 보스별 완료 여부, 주간 보스 처치 횟수 확인.
- `/캐릭터 스케줄러갱신`: 직접 갱신. 5분 이내에는 기존 기록 표시.
- 자동 수집은 매시간 시도합니다. 한국 날짜별 마지막 수집 상태를 저장하며 **최근 14일**을 조회합니다. 봇 중단 기간을 과거 조회로 자동 보충하지는 않습니다.
- 게임에 접속하지 않았거나 API가 데이터를 제공하지 않은 경우 이전 상태를 지우거나 전부 미완료로 만들지 않습니다. 조회 화면에 기준일과 수집 시각을 표시합니다.
- 보스 완료 상태를 파티 동행자·클리어 시간·드롭·판매 정보로 해석하지 않습니다. 파티 클리어 기록이나 정산을 자동 확정하지 않습니다.

### 호출 제한과 운영

동일 키의 요청은 공간이 달라도 직렬화하며 250ms 간격·10초 타임아웃을 적용합니다. 하루 호출 예산은 키별 900회로 DB에 기록하며 재시작해도 유지합니다. 다른 사용자 키의 실패/예산 소진은 나머지 사용자의 수집을 중단하지 않습니다. 같은 키를 외부 서비스에서 사용한 호출은 이 예산에 집계되지 않습니다.

고레벨 캐릭터 스펙 수집에는 약 15~17회 요청, 스케줄러는 1회 요청이 필요합니다. 캐릭터 수가 많으면 개발 단계 키의 호출 한도로 일부 자동 갱신이 다음 날로 지연될 수 있습니다. 서버가 꺼져 있거나 참가 자격을 잃으면 자동 수집하지 않습니다. API 이력에는 보관 기간을 적용하며 수동 환산 기록은 별도로 유지합니다.

### 환산

Maple Scouter 환산은 넥슨 API 제공값이 아닙니다. Maple Scouter 약관 제15조는 자동 접근 및 다른 도구의 데이터 소스로 사용을 금지하므로, 허용된 연동 경로가 확보되기 전에는 수동으로 기록합니다.

```text
/캐릭터 환산기록 캐릭터:도토리검사 수치:65000 종류:헥사
/캐릭터 환산기록 캐릭터:도토리검사 수치:50000 종류:주스탯
```

주스탯/헥사를 구분하고 시각·직전 기록 대비 증감을 표시합니다. `6.5` 대신 `65000`처럼 실제 수치를 입력합니다.
