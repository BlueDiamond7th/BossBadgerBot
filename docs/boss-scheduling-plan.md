# 보스 일정 기능 기획서 — 디스코드 사용성 보완판

작성일: 2026-11-14 · 상태: 첫 구현 반영, 실서버 검증 전 · 대상: BossBadgerBot

## 1. 방향과 초안에서 바꾼 점

**파티장은 시간을 한 번 정하고, 파티원은 평소에는 한 번 누르거나 예외가 있을 때만 응답한다.** 날짜 입력·매주 출석 체크·채팅 검색을 반복하게 만들지 않는 것이 목표다.

| 초안의 불편 | 보완안 |
|---|---|
| 날짜·시간·보스·소요 시간 등을 처음부터 입력 | 필수 입력은 출발 시간 하나. 파티 구성과 기본값을 가져온 뒤 미리보기에서 필요한 항목만 변경 |
| 참석 버튼을 찾은 뒤 개인 화면에서 다시 응답 | 공개 카드의 참석·불참·미정 버튼으로 즉시 저장 |
| 매주 모든 파티원이 참석을 다시 눌러야 함 | 본인이 한 번 동의한 정기 참석 유지. 불참·시간 변경 등 예외가 생긴 회차만 재응답 |
| 가능/조정 가능을 별도 입력 | 첫 버전은 가능한 후보만 여러 개 선택. 전부 가능·전부 불가 바로 응답 제공 |
| 매번 참가 현황 확인 화면을 따로 열어야 함 | 소규모 파티는 공개 카드에 이름까지 표시해 바로 확인 |
| 공개 카드가 채팅에 묻힘 | 기존 보스방 관리판에 다음 일정과 내 일정 진입점 제공 |
| 반복과 출발 알림이 후순위 | 첫 운영 버전에 정기 일정·예외 변경·출발 알림 포함 |
| 소요 시간만 달라져도 전원 응답 초기화 | 실제 출발 시간·참가 조건에 영향을 주는 변경만 재확인 |
| 매주 진행 완료를 수동으로 눌러야 함 | 시간이 지난 회차는 지난 일정으로 분류. 실제 클리어와 분리 |

아래 버튼 이름과 기본값은 제안이다. 기존 코드에 기능을 구현하거나 실제 알림을 발송하는 문서는 아니다.

## 2. 첫 운영 버전의 범위

1. 일회성 또는 매주 같은 시간으로 일정 등록.
2. 후보 시간 2~5개를 놓고 가능한 시간 투표.
3. 공개 카드에서 참석·불참·미정 한 번 눌러 저장.
4. 본인이 선택하는 정기 참석과 이번 회차만 변경·취소.
5. 다음 일정 찾기, 같은 사람의 시간 중복 경고, 출발 전 알림.

캘린더를 따로 열거나 외부 사이트에 로그인하는 과정 없이 기존 파티와 디스코드 채널에서 끝낸다. 첫 버전의 조회·중복 검사는 현재 채널 기준이다. 다른 채널 일정까지 합쳐 보여 준다고 안내하지 않는다.

## 3. 일반 파티원의 사용 흐름

### 평소 참석할 때: 한 번 누르기

공개 일정 카드에서 참석을 누르면 해당 회차 응답이 즉시 저장된다. 확인창이나 저장 버튼을 추가하지 않는다. 개인에게만 짧게 저장 결과와 응답 변경 방법을 안내한다. 불참·미정도 같은 방식이다.

응답은 상태 지정이다. 참석을 두 번 눌러도 참석이 취소되지 않는다. 실수로 누른 경우 다른 응답을 눌러 바꾼다. 참석 응답은 시작 시각 전까지 변경할 수 있으며, 시작 후에는 관리자의 수정으로 이력을 남긴다.

### 매주 같은 파티에 참여할 때: 처음에 한 번 동의

정기 일정의 내 일정 화면에서 매주 이 시간 참석을 켤 수 있다. 단순히 지난주에 참석했다는 이유로 다음 주도 참석 처리하지 않는다.

- 동의 후 같은 반복 규칙의 향후 회차에는 정기 참석으로 표시한다.
- 이번엔 불참을 눌러도 그다음 주의 정기 참석은 유지한다.
- 정기 참석 해제는 앞으로의 회차에만 적용하고 과거 응답은 보존한다.
- 파티에서 제외되면 해당 정기 참석도 종료한다. 재합류해도 자동 복구하지 않는다.
- 출발 시간이 변경된 회차는 정기 참석도 재확인 필요로 바꾼다.
- 반복 시간 자체가 변경되면 새 시간에 다시 동의해야 한다. 예전 시간에 대한 동의를 새 시간에 적용하지 않는다.

공개 카드에는 정기 참석과 이번 회차에 직접 누른 참석을 구분해 표시한다. 파티장은 사람별 참석 근거를 확인할 수 있다.

### 이번 주만 어려울 때

이번엔 불참을 누르면 그 회차만 불참 처리한다. 불참 사유 작성은 요구하지 않는다. 확정된 일정에서 참석이 불참으로 바뀌면 파티장에게 해당 회차의 인원 부족을 한 번 안내하고 카드에 남긴다. 동일 상태 반복 클릭은 알림을 만들지 않는다.

대타 모집을 자동으로 시작하거나 다른 사람을 임의 배정하지 않는다. 파티장이 기존 파티 구성에서 인원을 정리하고 회차에 반영한다.

## 4. 파티장이 시간을 등록하는 흐름

### 정해진 시간 등록

파티 정보 → 일정 잡기 → 시간 바로 등록 → 출발 시간 입력 → 미리보기 → 게시.

필수 입력은 출발 시간 하나다. 입력 예시는 오늘 22:00, 내일 21:30, 토 22:00, 2026-11-21 22:00을 제공한다. 자유로운 문장 전체를 해석하는 대신 지원 형식을 명시한다. 요일만 입력하면 현재 이후 가장 가까운 해당 요일로 계산하고, 게시 전 전체 날짜·요일·시각을 반드시 보여 준다. 오늘의 이미 지난 시각은 다음 주로 조용히 넘기지 않고 오류로 안내한다.

미리보기 기본값:

- 파티원: 기존 파티 구성. 명단을 다시 고르지 않는다.
- 보스: 파티에 등록된 전체 보스. 일부만 갈 때에만 변경한다.
- 예상 소요 시간: 직전 설정이 있으면 재사용, 처음이면 60분. 15~240분 사이 조절 가능.
- 반복: 기본은 이번 한 번. 매주 같은 시간을 선택하면 요일·시각을 반복 규칙에 저장.
- 출발 알림: 기본 10분 전 한 번. 30분 전 또는 끄기로 변경 가능.

입력 화면 하나에 모든 선택을 몰아넣지 않고 미리보기의 시간 변경·보스 선택·반복·알림 설정에서 필요한 항목만 바꾼다. 선택 항목을 건드리지 않으면 바로 게시할 수 있다.

날짜와 시각은 한국 시간이며, 자정 부근은 토요일 00:30처럼 전체 날짜와 함께 재확인한다. 24:30처럼 모호한 입력은 받지 않는다. 과거 시각 등록은 막는다.

### 이번 회차만 바꾸기

일정 관리의 기본 변경 범위는 이번 회차만이다. 시간 변경 또는 이번 회차 쉬기를 선택한다. 이후 회차까지 바꾸려면 변경 범위를 별도로 선택해야 한다.

확정된 일정은 저장 전에 바뀌는 시각과 재확인할 인원을 보여 준다. 변경 사유는 선택 입력으로 두고, 일정 충돌이나 불참자를 남긴 채 확정할 때만 짧은 확인 사유를 받는다.

## 5. 후보 시간 투표 — 입력을 줄인 방식

### 파티장

1. 일정 잡기 → 시간 투표를 선택한다.
2. 후보를 최대 5줄로 입력한다. 한 줄에 날짜·요일과 시각 하나를 받는다.
3. 반복 일정에서 시작했다면 원래 시간이 첫 후보로 미리 들어간다.
4. 파싱한 실제 날짜와 중복 후보 제거 결과를 확인하고 게시한다.

마감은 기본으로 게시 24시간 뒤를 제안하되 가장 이른 후보 출발 1시간 전을 넘지 않게 한다. 이미 임박한 후보라 유효한 마감을 만들 수 없으면 파티장에게 마감 시각 수정 또는 바로 등록을 안내한다. 시간 조율을 시작할 때 입력값 검증을 끝내고 응답자에게 잘못된 후보를 보여 주지 않는다.

### 파티원

공개 카드의 투표하기 → 개인 화면에서 가능한 후보 여러 개 선택 → 저장. 새 날짜나 시각을 타이핑할 필요가 없다.

- 모든 후보가 괜찮으면 전부 가능 한 번으로 저장.
- 모두 어렵다면 전부 불가 한 번으로 저장.
- 저장 후 선택하지 않은 후보는 불가. 저장 전에는 미응답이다.
- 답을 바꾸려고 다시 열면 기존 선택을 미리 표시한다.
- 조정 가능과 자유 의견 수집은 첫 버전에서 제외한다. 복잡한 예외는 채팅으로 협의하고 결과만 반영한다.

예시:

    이번 회차 시간 투표 · 6명 중 5명 응답
    ① 토 21:00  가능 4 · 불가 1 · 미응답 1
    ② 토 22:00  가능 5 · 불가 0 · 미응답 1  ← 추천
    ③ 일 20:00  가능 3 · 불가 2 · 미응답 1
    [투표하기] [내 일정] [관리]

추천 순서는 불가 인원이 적음 → 가능 인원이 많음 → 이른 시각이다. 후보는 생성 시 순서를 유지하고 추천 표시만 바꿔 응답 중 선택지가 움직이지 않게 한다.

마감 후 자동 확정하지 않는다. 파티장이 추천 시간을 눌러 확정한다. 해당 후보에 가능으로 답한 사람은 참석을 이어받아 다시 출석 버튼을 누르지 않아도 된다. 불가는 불참, 미응답은 미응답으로 유지한다. 불참·미응답 인원이 있으면 확인 후 확정한다.

전원 불가 또는 전원 미응답이면 좋은 시간이라고 추천하지 않는다. 후보 다시 제안과 채팅 협의 후 직접 확정을 제공한다. 후보를 바꿔도 유지된 시각에 대한 응답은 보존하고, 새 후보만 미응답으로 추가한다. 날짜·시각을 수정한 후보는 새 후보로 취급하며 변경된 선택지를 다시 알린다.

## 6. 공개 카드와 일정 찾기

### 공개 카드에서 필요한 정보를 바로 확인

    목요일팟 · 11/21(토) 22:00~23:00 · 한국 시간
    하드 세렌 / 카오스 칼로스

    시간 확정 · 참석 4/6
    참석: 도토리, 모찌
    정기 참석: 감자, 밤
    불참: 콩   미응답: 쌀
    출발 10분 전 알림

    [참석] [이번엔 불참] [미정] [내 일정] [관리]

위 날짜는 화면 설명용 예시다. 실제 화면에는 연도가 필요하면 포함하고, 오늘·내일 표시는 날짜·요일과 함께 사용한다. 긴 명단은 요약하고 상세 화면으로 넘긴다.

버튼은 한 줄에서 읽히는 짧은 이름으로 유지한다. 응답자 이름 표시는 등록 캐릭터명 기준이며 멘션 알림을 동반하지 않는다. 투표·응답 때는 기존 공개 카드를 갱신하고 새 공지를 계속 만들지 않는다. 일정 관리 권한이 없는 사람이 관리 버튼을 누르면 본인 일정 확인 화면으로 안내한다.

### 채팅에 묻힌 뒤 찾기

- 기존 보스방 관리판에 앞으로 가장 가까운 일정 3개와 일정 목록·내 일정 버튼을 추가한다.
- 일정 목록은 앞으로 7일을 기본 범위로 보여 주고 오늘·내일·요일별로 묶는다. 다음 7일도 이동 가능하다.
- 내 일정은 내가 포함된 파티만 시간순으로 보여 준다. 불참·재확인 필요 상태도 숨기지 않는다.
- 명령어는 /일정 목록, /일정 내일정, /일정 생성 파티를 기본 진입점으로 둔다. 대부분의 행동은 카드 버튼으로 끝낸다.
- 목록·내 일정·생성 미리보기는 개인 화면으로 연다. 파티장이 게시한 일정 카드와 필요한 확정·변경·출발 공지만 채널에 보낸다.
- 관리판 고정은 선택 사항이다. 고정을 강제하지 않고 명령어로도 즉시 다시 열 수 있게 한다.

정기 일정은 가까운 4주까지 DB에 만들 수 있지만 미리 네 장씩 게시하지 않는다. 각 정기 일정의 가장 가까운 미진행 회차 하나만 자동 게시한다. 그 회차가 지나면 다음 회차 카드를 게시하고 관리판의 링크를 갱신한다. 지난 카드는 지난 일정임을 표시해 남기며 버튼은 이력·다음 일정 확인용으로 바꾼다.

과거 알림에는 그 회차의 날짜·시간을 그대로 적고 특정 회차 식별자를 연결한다. 다음 주 카드로 연결을 덮어써 지난 알림의 의미가 바뀌지 않게 한다. 완료 버튼은 매주 누르지 않아도 된다. 시간이 지나면 지난 일정으로 분류하되 실제 출발·클리어 완료로 기록하지 않는다.

## 7. 변경·인원·충돌 규칙

### 바뀐 부분만 재확인

| 변경 | 응답 처리 |
|---|---|
| 출발 날짜·시각 변경 | 해당 회차의 기존 참석·불참을 이전 응답으로 보존하고 재확인 필요로 표시 |
| 투표 후보 추가 | 기존 후보 응답 보존, 새 후보만 미응답 |
| 메모·표시명·알림 시각 변경 | 참석 응답 유지 |
| 소요 시간 증가 | 참석 응답 유지, 새 충돌 검사. 충돌 발생 인원만 재확인 필요 |
| 보스 추가·교체 | 실제 참가 조건 변경으로 보고 해당 회차 재확인 요청 |
| 보스 제외·소요 시간 단축 | 기존 응답 유지, 변경 내역 표시 |
| 인원 추가·제외 | 남은 인원의 응답 유지. 신규 인원은 미응답, 제외 인원의 응답은 이력 보존 |

회차에는 생성 시점의 캐릭터·등록자·대상 보스를 저장한다. 원래 파티를 편집해도 이미 공지된 회차를 몰래 바꾸지 않는다. 파티 구성 변경이 있으면 관리자에게 현재 구성 적용을 제안하고, 영향을 받는 예정 회차를 미리 보여 준다. 보스의 난이도 변경도 참가 조건 변경으로 처리한다.

### 시간 중복 경고

- 같은 채널 안의 다른 확정·검토 필요 회차와 시작~종료 구간을 비교한다.
- 캐릭터가 달라도 등록자가 같으면 같은 사람의 충돌이다.
- 예정 종료와 다음 시작이 같은 경우 충돌로 막지 않는다. 이동·준비 여유가 없다는 안내만 표시한다.
- 충돌 때문에 무조건 저장을 막지 않는다. 파티장이 기존 일정 조정 또는 확인 사유를 남긴 채 확정을 선택한다.
- 자동 생성한 정기 회차가 충돌하면 검토 필요로 만들고 관리자에게 알린다. 출발 알림은 확정 전까지 보류한다.

기본 소요 시간은 실제 소요 시간의 추정값이므로 충돌 경고와 확정된 참석 약속을 구분해 표시한다. 휴면 파티 때문에 모든 일정을 매주 막는 방식은 피한다.

### 취소와 권한

파티 생성자 또는 해당 채널/스레드 관리자가 일정 생성·확정·변경·취소를 맡고, 대상자는 자기 응답만 바꾼다. 조작할 때마다 현재 채널 접근과 대상자 여부를 확인한다.

파티 보관 시 정기 생성을 중단하고 예정 회차를 취소한다. 미리 취소 대상 수를 보여 주며, 이미 확정된 회차는 취소 알림을 보낸다. 파티 복원은 일정을 자동 재개하지 않는다.

공개 카드의 이전 버전에서 응답해도 최신 회차가 같은 시간이고 대상자가 유효하면 처리한다. 시간·후보·대상자가 달라졌을 때만 최신 내용을 다시 보여 준다. 단순 응답 수 갱신 때문에 다른 사람의 참석 클릭이 오래된 요청으로 거절되지 않게 한다.

## 8. 알림 — 필요한 사람에게만

| 상황 | 기본 동작 |
|---|---|
| 최초 투표 게시 | 회차 대상자에게 한 번 멘션 |
| 시간 바로 등록·투표 결과 확정 | 확정 시간과 대상자에게 한 번 멘션 |
| 매주 동일 회차 자동 게시 | 카드만 게시. 매주 게시 알림 멘션은 추가하지 않음 |
| 출발 10분 전 | 참석·정기 참석·미정·미응답·재확인 필요 대상자에게 한 번 알림. 불참자는 제외 |
| 확정 시간 변경·취소 | 변경 전후와 영향받는 대상자에게 안내 |
| 참석에서 불참으로 변경 | 파티장에게 인원 부족 안내. 같은 상태 반복 입력은 추가 알림 없음 |
| 투표 마감 | 파티장에게 한 번 결과 확인 요청 |
| 미응답자 재촉 | 파티장이 명시적으로 누를 때만. 미응답자 대상, 최소 1시간 간격·회차당 최대 2회 |

원래 채널에서만 안내하고 첫 버전은 DM을 보내지 않는다. 관리자 안내가 같은 회차에서 짧은 시간에 이어지면 합쳐 중복 멘션을 줄인다. 멘션 대상은 발송 직전 채널 접근을 확인한다.

출발 알림 예시:

    10분 뒤 22:00, 목요일팟 출발 예정입니다.
    참석 4/6 · 불참 1 · 미응답 1
    [일정 보기] [참석 변경]

참석 인원이 부족해도 확정된 출발 시간을 임의로 취소하지 않는다. 부족 현황을 함께 표시한다. 알림은 실제 접속 여부나 디스코드 사용자의 알림 수신을 보장하지 않는다.

출발까지 알림 간격보다 적게 남았을 때 확정·변경하면 그 공지로 안내를 합치고 출발 알림을 추가 발송하지 않는다. 취소·변경된 회차의 이전 알림 작업은 무효화한다.

## 9. 꼭 처리할 예외

- 파티장이 없어도 기존 채널/스레드 관리자가 확정·취소할 수 있다.
- 새 대상자는 이전 정기 참석 동의를 이어받지 않는다. 같은 계정의 캐릭터 교체는 사람은 같지만 해당 회차 조건을 다시 확인한다.
- 공개 카드가 지워져도 일정은 남는다. 관리판과 내 일정에서 다시 열고 관리자가 재게시할 수 있다.
- 비공개 화면의 만료·삭제는 저장된 투표와 참석 응답에 영향을 주지 않는다.
- 봇 재시작 후 등록된 반복 규칙·회차·응답·알림을 복구한다. 매주 같은 회차를 중복 생성하지 않는다.
- 알림 전송 권한이 없으면 관리 화면에 실패 상태를 보여 준다. 삭제·재게시를 무한히 반복하지 않는다.
- 시작한 회차의 투표·셀프 참석 변경을 닫고 다음 일정과 과거 이력을 안내한다.
- 시간이 지나도 API의 실제 보스 클리어 여부를 자동으로 바꾸지 않는다.

## 10. 첫 배포의 완료 기준

개발은 아래 순서로 진행하되, **1~3단계가 모두 갖춰져야 첫 운영 버전으로 배포한다.** 정기 파티에 반복 일정과 출발 알림이 없으면 기존 채팅보다 매주 손이 더 가기 때문이다.

| 단계 | 구현 내용 |
|---|---|
| 1 | 기존 파티 연결, 시간 간편 입력, 공개 카드, 한 번 눌러 응답, 관리판·내 일정 진입 |
| 2 | 간단한 후보 투표, 매주 반복, 정기 참석 동의, 이번 회차만 변경·취소, 중복 경고 |
| 3 | 10분 전 알림, 변경·취소 알림, 재시작 복구, 권한·동시 조작·긴 텍스트 검증 |

첫 범위에서 제외: 전체 주간 시간표 작성, 별도 웹 화면, 외부 캘린더 연동, 자동 대타 모집, 보스별 회차 캐릭터 교체 UI, 자동 음성 이동, 서버 전체 일정 통합. 여러 파티를 이어서 도는 경우의 앞 파티 종료 후 출발도 후속으로 둔다. 첫 버전은 실제 시각이 있는 일정으로 등록한다.

## 11. 실사용 검증 시나리오

| 상황 | 기대 결과 |
|---|---|
| 모바일에서 이번 주 참석 | 공개 카드의 참석 한 번. 모달·추가 저장 화면 없음 |
| 매주 같은 파티 참석 | 정기 참석 동의 후 매주 버튼을 다시 누를 필요 없음 |
| 이번 주만 불참 | 한 번 눌러 이번 회차만 불참. 다음 주 동의 유지 |
| 후보 5개 중 3개 가능 | 날짜 타이핑 없이 다중 선택과 저장으로 완료 |
| 모든 후보 가능 | 전부 가능 한 번으로 저장 |
| 시간이 바뀐 정기 파티 | 예전 동의를 새 시간에 사용하지 않고 재확인 필요로 표시 |
| 채팅이 많이 쌓임 | 관리판 또는 내 일정에서 다음 일정에 바로 접근 |
| 같은 사람이 두 캐릭터로 겹친 시간 배정 | 이름이 다른 캐릭터여도 시간 중복 안내 |
| 응답을 여러 명이 동시에 누름 | 전원 응답 보존. 응답 수 변경 때문에 다른 사람의 클릭이 거절되지 않음 |
| 봇 재시작·같은 버튼 재전송 | 회차·응답·알림 작업을 중복 생성하지 않음 |

목표 수치는 구현 검증용 제안값이다. 시간 바로 등록은 진입 버튼부터 게시까지 기본 경로 5회 이내 조작과 시간 입력 한 번, 일반 참석 응답은 공개 카드에서 한 번, 기존 투표 수정은 선택 내용 복원 상태에서 진행되는지 확인한다. 실제 모바일 디스코드에서 3인·6인 파티로 각각 검증하고, 2주 이상 정기 파티를 운영하며 미응답 관리와 알림 빈도를 확인한다.

## 12. 구현 메모

사용자는 파티·이번 일정·매주 반복만 이해하면 된다. 규칙·회차·버전·예약 작업은 내부 개념으로 관리한다.

현재 Node.js·SQLite 구조를 유지한다. 저장 단위는 정기 규칙, 실제 회차, 회차 인원·보스 사본, 시간 후보, 사용자 응답, 정기 참석 동의, 변경 이력, 알림 작업이다. 모든 데이터는 서버·채널로 구분하며 시각은 UTC로 저장하고 입력·표시는 한국 시간으로 처리한다.

구현 시 구분해야 할 버전:

- 일정 조건 버전: 출발 시각·대상자·보스 등 참가 조건이 바뀔 때 변경.
- 응답 갱신: 참석 수가 변해도 일정 조건 버전을 바꾸지 않음.
- 정기 규칙 버전: 반복 시각 변경 시 정기 참석 동의 재확인에 사용.

일정 생성·수정·응답은 트랜잭션과 요청 ID로 처리한다. 정기 회차는 규칙과 원래 회차 날짜를 고유키로 관리해 이번 주 시간 변경 후에도 중복 생성되지 않게 한다. 응답자가 많아도 공개 카드 갱신은 회차별로 직렬화해 마지막 상태를 보여 준다.

알림은 개인 메시지 토큰에 의존하지 않고 봇이 저장된 채널로 발송한다. 회차·조건 버전·알림 종류별 작업을 저장하고 재시작 후 복구한다. 발송과 DB 기록 사이의 장애로 전송 결과가 불명확하면 자동 재전송을 반복하지 않고 상태와 수동 재알림 수단을 남긴다. 출발 전이며 예정 시각에서 10분 이내인 지연 작업만 복구 발송하고, 이미 시작한 회차에는 출발 알림을 보내지 않는다.

기존 연결 지점은 파티 규칙 src/service.js, 개인 조작 src/interactions.js, 화면 src/views.js, 관리판 src/board.js, 시작·종료와 정기 처리 src/bot.js다. 첫 구현은 schedule.js, schedule-views.js, schedule-interactions.js, schedule-worker.js로 분리했다. 실제 사용법과 검증 범위는 README의 2026-11-14 보스 일정 항목을 따른다.
